## Formula spine

### Dashboard

The dashboard is mostly count formulas over `Holds Only P2`, `All Field Open Hold`, and `IX Placards Photos`.

Representative formulas:

- `A6 = COUNTA('Holds Only P2'!A2:A[current holds last row])`
- `C6 = COUNTIF('Holds Only P2'!W2:W[current holds last row],"Yes")`
- `F6 = COUNTA('All Field Open Hold'!A2:A[current open-hold last row])`
- bucket rows use `COUNTIF` / `COUNTIFS` against `Holds Only P2!U:U` and `Holds Only P2!W:W`

Interpretation:

- column `U` on `Holds Only P2` is the reason bucket
- column `W` on `Holds Only P2` is field-task-open status from placards / photos

In the Part 1 derivative workbook, the dashboard is rewritten as `Part 1 All - Dashboard`. Its design block starts at `E26` and counts `Part 1 Design Queue!M:M` flags:

- `Missing design correction task`
- `Design correction open`
- `Design correction completed - IX still held`
- `Field completed >14 days`
- `Design correction needs review`

It links to `Part 1 Design Summary`, which rolls design-related Part 1 holds up by raw IX reason, matching Pre-Install / As-Built correction task type, and follow-up signal.

Part 1 reason bucket inputs use a single selected source reason, not a concatenation of every populated reason field. Selection priority is `IXP1 Rejection Reason`, then `Request IXP1 Reason unable to submit`, then receive/process unable-to-submit fields, then `Prepare IXP1 Reason unable to Submit`, with prepare used only when the higher-priority fields are blank.

The Part 1 dashboard reason table uses Part 1-native labels instead of the Part 2 reason list. The baseline labels include `(blank)`, `Missing Signature`, `CAD Update Needed`, `Customer`, `System Size`, `Missing Portal Access`, `Missing UB`, `Utility`, `Customer; Utility`, `Missing HOI`, and `Customer Signature`; the generator appends any additional selected reason bucket found in the current export.

### WoW Comparison

This tab compares current `Holds Only P2` counts against `Last Week Holds`.

Representative formulas:

- `A5 = COUNTA('Holds Only P2'!A2:A[current holds last row])`
- `C5 = COUNTA('Last Week Holds'!A2:A[current snapshot last row])`
- `E5 = A5-C5`
- `G5 = IF(C5=0,"N/A",(A5-C5)/C5)`
- per-bucket rows count `U:U` in both sheets, compute delta, then label `Up` / `Down` / `Same`

### Holds Only P2 helper columns

Raw data occupies columns `A:S`. The workbook relies on helper / formula columns beginning at `T`.

Key helper columns observed in the current workbook:

- `T`: derive high-level task phase from task name
- `U`: classify blocker bucket from reason text across `Q:R:S`
- `V`: concatenate reason text into one readable field
- `W`: mark whether related field work already exists by matching `IX Placards Photos!B:B`
- `X`: running count within each `U` bucket
- `Y`: drilldown search key built from `U|X`
- `Z`: normalize field-related flags
- `AA:AC`: look back into `All Field Open Hold` for state and utility details, including extracting utility text from HTML-style anchor content

Representative formulas from row 2:

- `T2`: classify `Prepare` / `Request` / `Receive`
- `U2`: bucket reasons such as `Field work`, `WAITING FOR M2 APPROVAL`, `Missing FIN`, `Missing HOI`, and `(blank)`; the Salesforce placeholder value `REASON UNABLE TO SUBMIT` is folded into `(blank)`.
- `W2`: `IF(COUNTIF('IX Placards Photos'!$B:$B,A2)>0,"Yes","No")`
- `AA2:AC2`: `INDEX/MATCH` lookups into `All Field Open Hold`

### Task Log Rollup

This sheet aligns each `Holds Only P2` project with task-log counts from `Task Log`.

Representative formulas:

- `A2 = 'Holds Only P2'!A2`
- `B2 = IF($A2="","",IFERROR(INDEX('Task Log'!$M$2:$M$80000, MATCH($A2&"|"&$C2,'Task Log'!$O$2:$O$80000,0)), ""))`
- `C2 = IF($A2="","",COUNTIF('Task Log'!$A$2:$A$80000,$A2))`

### Task Log helper columns

`Task Log` reserves helper columns `J:O` for the task-log-summary path.

- `J` stores the project code used as the rollup key.
- `M` stores the flattened summary line: `Subject` plus `Full Comments` when comments exist.
- `N` stores the per-project occurrence number as rows are scanned top-to-bottom.
- `O` stores the exact last-match lookup key in the form `Project|Occurrence`.

This preserves the old `LOOKUP(2,1/(...))` "last log wins" behavior without keeping expensive array formulas in `Holds Only P2!AH` and `Task Log Rollup!B`.

### Drilldown sheets (`R - ...`)

Each drilldown sheet follows the same pattern:

- header cells count the bucket and split by field task open `Yes` / `No`
- visible rows use column `O` as a search key
- displayed columns use `INDEX/MATCH` into `Holds Only P2` keyed by `Holds Only P2!Y:Y`

This means the drilldowns do not define categories themselves; they render whichever records `Holds Only P2!U` already categorized.

### Cycle time surfaces

`Cycle Time Summary` and `Cycle Time Dashboard` are script-owned executive views. They use `All Field Open Hold` for the active Open/Holding population and `All-Projects-All-Time.csv` for milestone dates. `Cycle Time Detail` is hidden and stores the precomputed row-level measurements that the dashboard filters by lookback, scope, category type, cohort, and cycle.

Interpretation:

- active pipeline views exclude `Canceled`, `Cancelled`, and `Complete`
- completed-project cycle time uses `Status = Complete`
- FIN/FIV age uses `Electrical FIN Received` because the current source exports do not contain a separate `FIV Received` header
- dashboard cell `B4` is the lookback control used by the visible cohort table

## Practical implications for future edits

- If counts are wrong, inspect `Holds Only P2!U:W` before changing dashboard formulas.
- If utility names are wrong, inspect `All Field Open Hold` and `Holds Only P2!AA:AC`.
- If a drilldown tab is missing or miscategorized records, inspect `Holds Only P2!Y` search keys and the bucket formula in `U`, not the drilldown tab first.
- If task-log summaries change after a formula optimization, verify that the workbook still returns the last Task Log entry for each project rather than the first one encountered.
- If week-over-week numbers look wrong, confirm `Last Week Holds` was snapshotted before the latest refresh.
- If cycle-time counts look wrong, inspect `All Field Open Hold` active-status filtering and `All-Projects-All-Time.csv` milestone dates before changing the dashboard sheets.
- If you are adding a new blocker bucket, update both the `Holds Only P2!U` classification logic and the visible dashboard / drilldown surfaces that report that bucket.
- If the task is on `Mierins Remix`, prefer workbook-only edits, validate `State` from the master dataset, and keep `Closeout Work` synchronized with the projects excluded from `Main`.
